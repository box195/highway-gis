# 월별 점검계획 조회

점검계획 탭의 **조회할 점검계획**에서 현재 데이터팩 또는 2026년 4~10월 원본 계획을 선택합니다. 이전 달은 날짜순 목록으로 표시하며, 지사 필터와 거점·선로·설비 검색을 제공합니다. 각 일정을 펼치면 설비별 원본 점검 표기와 원본 시트를 확인할 수 있습니다.

현재 데이터팩의 달력·일정 선택·지도 강조 기능은 유지합니다. 원본 파일 조회는 시설물 데이터팩이나 현재 일정을 덮어쓰지 않으며, 월 변경 시 현재 점검일의 지도 강조를 해제합니다. 같은 날짜·지사·대상·설비 구분에 속한 표기를 한 목록 항목으로 묶고 원본 셀 참조를 보존합니다. 표기가 없는 셀은 일정으로 생성하지 않습니다.

## 원본 선택과 범위

- 같은 달에 총괄파일과 팀 파일이 함께 있으면 총괄파일을 우선합니다.
- 4·5·7·8·9·10월은 총괄파일의 5개 지사 시트를 사용합니다.
- 6월은 제공된 1팀 파일의 2개 지사 시트만 포함하고 화면에 범위를 표시합니다.
- 7개월에서 일정 묶음 551건, 원본 점검 표기 2,278개를 추출했습니다. 월말을 벗어난 날짜나 중복 셀은 없습니다.
- 인력 이름·근무자 정보는 추출하지 않습니다. 엑셀 원본은 읽기만 합니다.

## 자료 갱신

1. `scripts/extract-inspection-history.py SOURCE_DIRECTORY PRIVATE_OUTPUT.json`으로 외부 작업 폴더에 추출합니다. 평문 중간 파일을 저장소 내부에 쓰지 못하도록 검사합니다. 실행 환경에는 `openpyxl`이 필요합니다.
2. 월·원본 시트·셀 값·원본 SHA-256을 확인합니다.
3. `node scripts/encrypt-inspection-history.mjs PRIVATE_OUTPUT.json`으로 기존 데이터팩과 동일한 암호화 형식의 `data/inspection-history.enc.json`을 생성합니다. 기존 시설물 데이터와 암호화 데이터팩은 수정하지 않습니다.
4. 자료 또는 UI를 변경하면 `inspection-history.mjs`와 연결된 모델·암호화 파일의 조회 버전을 함께 갱신합니다.

## 검증

`npm run test:inspection`은 월·지사·검색·빈 결과, 원본 셀 중복 여부, 6월 범위 표시, 암호화 파일 해독, 다른 월의 달력 일수·시작 요일을 검사합니다. 원본 대조에서는 선택한 7개 파일의 해시 불변과 2,278개 셀 값의 일치를 확인했습니다. 브라우저에서 총괄 월 선택, 지사 필터, 상세 펼치기, 검색 결과 없음, 6월의 부분 자료 표시, 현재 달력 복귀, 모바일 접근을 확인했습니다.

현재 점검계획과 과거 원본은 별개 조회입니다. 과거 원본의 추가 지사는 대응되는 GIS 시설물 데이터가 없어도 목록에서 읽을 수 있으며, 위치를 임의 추정해 지도에 연결하지 않습니다.
