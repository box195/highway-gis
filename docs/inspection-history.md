# 월별 점검계획 조회

점검계획 탭의 **조회할 점검계획**에서 현재 데이터팩 또는 2026년 4~10월 원본 계획을 선택합니다. 이전 달도 기존 달력과 날짜별 일정 카드를 그대로 사용합니다. 동서울지사·경기광주지사를 함께 보거나 한 지사를 선택할 수 있습니다. 날짜와 일정을 선택하면 기존 상세 점검표에서 설비별 항목과 원본 표기를 확인합니다.

원본 파일 조회는 시설물 데이터팩이나 현재 일정을 덮어쓰지 않으며, 월 변경 시 선택한 점검일의 지도 강조를 해제합니다. 같은 날짜·지사·거점의 전송·유선·선로 점검 표기를 하나의 거점 일정으로 묶고 원본 셀 참조를 보존합니다. 선로 일정은 인공·수공 번호를 해당 지사의 기존 시설물과 연결합니다. 위치를 찾지 못하면 임의의 좌표로 연결하지 않습니다. 표기가 없는 셀은 일정으로 생성하지 않습니다.

## 원본 선택과 범위

- 같은 달에 총괄파일과 팀 파일이 함께 있으면 총괄파일을 우선합니다.
- 모든 월에서 동서울지사·경기광주지사만 추출하며 다른 지사 자료는 암호화 배포 파일에서도 제외합니다.
- 4·5·7·8·9·10월은 총괄파일, 6월은 제공된 1팀 파일을 사용합니다.
- 7개월에서 원본 묶음 249건, 원본 점검 표기 837개를 추출했습니다. 월말을 벗어난 날짜나 중복 셀은 없습니다.
- 인력 이름·근무자 정보는 추출하지 않습니다. 엑셀 원본은 읽기만 합니다.

## 자료 갱신

1. `scripts/extract-inspection-history.py SOURCE_DIRECTORY PRIVATE_OUTPUT.json`으로 외부 작업 폴더에 추출합니다. 평문 중간 파일을 저장소 내부에 쓰지 못하도록 검사합니다. 실행 환경에는 `openpyxl`이 필요합니다.
2. 월·원본 시트·셀 값·원본 SHA-256을 확인합니다.
3. `node scripts/encrypt-inspection-history.mjs PRIVATE_OUTPUT.json`으로 기존 데이터팩과 동일한 암호화 형식의 `data/inspection-history.enc.json`을 생성합니다. 기존 시설물 데이터와 암호화 데이터팩은 수정하지 않습니다.
4. 자료 또는 UI를 변경하면 `inspection-history.mjs`와 연결된 모델·암호화 파일의 조회 버전을 함께 갱신합니다.

## 검증

`npm run test:inspection`은 암호화 자료의 두 지사 제한, 원본 셀 중복과 누락 여부, 거점 일정 병합, 지사별 인공·수공 연결, 달력의 월별 일수와 시작 요일, 현재 일정 보존을 검사합니다. 과거 원본도 현재 일정과 같은 달력·날짜 선택·상세 점검표를 사용합니다.
